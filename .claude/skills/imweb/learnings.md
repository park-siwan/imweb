## Handlebars / annotation

### 패널은 위젯 "생성 시 1회" 빌드 — 코드 수정해도 기존 위젯엔 반영 안 됨
- **증상**: 코드에서 `@label`·필드 순서·그룹·`@default` 값을 바꿔도 기존 위젯 패널이 그대로.
- **원인**: imweb은 위젯 **처음 만들 때** annotation으로 패널을 1회 구성하고, 이후 코드 저장은 **렌더(HTML/CSS 시각)만** 갱신. 패널 스키마·저장된 값은 안 건드림(저장 데이터 보호).
- **무엇이 반영되나**:
  - CSS **규칙**(레이아웃·padding·flex 등) → 재붙여넣기로 ✅
  - `@default` **값**, `@label`, 필드 **순서/그룹**, 필드 추가 → 기존 위젯 ❌
- **해결**: 값은 **패널에서 직접** 변경. 새 라벨/순서/필드를 패널에 보려면 **새 위젯으로 생성**. `@default`는 "미래의 새 위젯/새 아이템 초기값"일 뿐.
- **item 디폴트 한계**: `@default`는 필드당 값 1개 → item 12개에 서로 다른 이름 미리 못 채움(§8.7). 차별화된 프리필 필요하면 item 대신 **고정 textfield 슬롯**(각자 @default).
- **워크플로**: 필드(스키마)를 바꿀 때마다 새 위젯 생성 + item 데이터 재입력이 반복된다. → ① **데이터 입력 전에 필드 세트를 최대한 확정**(item 하위 20필드 한도 안에서 미리 다 넣기), ② **개발 중엔 item 1개만 채워 테스트**, 디자인 확정 후 전체 입력.
- **item 필드 재정렬/추가 = 데이터 리셋**: 기존 위젯에 새 필드는 뜨지만, item 필드 **순서를 바꾸거나 세트를 변경하면 입력 데이터가 디폴트로 초기화**된다(label이 "카테고리"로 도배). → 필드는 **끝에 append만**, 순서 변경 금지. CSS-only 변경은 item 데이터를 건드리지 않으므로, **스키마 확정 후엔 스타일만 수정**하면 데이터 안전.

## CSS cascade · specificity

### color @default 의 알파(투명도)가 실제론 안 먹음 → FF(불투명)로 떨어짐
- **증상**: `@default #33333380`(50%)인데 패널 필드·렌더는 `#333333FF`(불투명). 컬러피커에서 알파 % 줘도 렌더 투명도 안 먹힘.
- **원인**: imweb이 색상값 알파를 불안정하게 처리(8-hex 알파를 FF로 떨굼). §3.3의 "8-hex 알파 지원"과 실제 동작이 다름.
- **해결**: 색(RGB)과 투명도를 **분리**. 컬러는 color 필드, 투명도는 별도 `textfield %` 필드, CSS `color-mix(in srgb, {{color}} {{opacity}}%, transparent)` 로 합성. 토큰 알파와 무관하게 항상 먹는다.
  ```css
  --bg: color-mix(in srgb, {{color-bg}} {{text-bg-opacity}}%, transparent);
  ```
