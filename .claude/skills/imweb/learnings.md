## Handlebars / annotation

### item 배열 최대 20개 — `@length` 30 줘도 20에서 캡
- **증상**: `@length 30` 으로 줘도 패널에서 아이템이 **20개까지만** 추가/노출됨.
- **원인**: imweb이 item 타입 배열을 **최대 20개로 캡**(하위 필드 20개 한도와 별개의, 아이템 개수 한도). 30 등 초과 지정은 자동으로 20으로 낮춰짐.
- **해결**: `@length`는 **20 이하**로. 20개 초과 항목이 필요하면(예: 모바일 카테고리 30개) 단일 item으로 불가 → 설계 재고(여러 위젯 분할 등). item은 위젯당 1종(§3.3)이라 한 위젯 내 우회도 없음.
- 참고: 빈 항목은 `{{#if label}}`로 감싸 미출력 → 20칸 다 안 채워도 빈 타일 안 생김.

### 패널은 위젯 "생성 시 1회" 빌드 — 코드 수정해도 기존 위젯엔 반영 안 됨
- **증상**: 코드에서 `@label`·필드 순서·그룹·`@default` 값을 바꿔도 기존 위젯 패널이 그대로.
- **원인**: imweb은 위젯 **처음 만들 때** annotation으로 패널을 1회 구성하고, 이후 코드 저장은 **렌더(HTML/CSS 시각)만** 갱신. 패널 스키마·저장된 값은 안 건드림(저장 데이터 보호).
- **무엇이 반영되나**:
  - CSS **규칙**(레이아웃·padding·flex 등) → 재붙여넣기로 ✅
  - `@default` **값**, `@label`, 필드 **순서/그룹**, 필드 추가 → 기존 위젯 ❌
- **해결**: 값은 **패널에서 직접** 변경. 새 라벨/순서/필드를 패널에 보려면 **새 위젯으로 생성**. `@default`는 "미래의 새 위젯/새 아이템 초기값"일 뿐.
- **item 디폴트 한계**: `@default`는 필드당 값 1개 → item 12개에 서로 다른 이름 미리 못 채움(§8.7). 차별화된 프리필 필요하면 item 대신 **고정 textfield 슬롯**(각자 @default).
- **워크플로**: 필드(스키마)를 바꿀 때마다 새 위젯 생성 + item 데이터 재입력이 반복된다. → ① **데이터 입력 전에 필드 세트를 최대한 확정**(item 하위 20필드 한도 안에서 미리 다 넣기), ② **개발 중엔 item 1개만 채워 테스트**, 디자인 확정 후 전체 입력.
- **코드 재저장 = 배치 위젯의 item 데이터 리셋(관찰)**: item 필드 변경뿐 아니라 **CSS만 바꿔 재저장해도** 데이터가 날아가는 정황. 정확한 트리거·정책 여부는 미확인. → **철칙: 코드(HTML/CSS/JS) 완전 확정 후 데이터는 맨 마지막에 한 번 입력.** 개발 중엔 데이터 넣지 말 것. 재입력 대비해 **시드 데이터를 repo 문서로 보관**(복붙용). (앞서 "CSS-only는 안전"이라 적었으나 오류 — 정정.)
- **부분 마이그레이션 관찰**: 스키마 변경 시 imweb이 item 데이터를 **@name+타입으로 부분 매칭 이전**하는 듯. 관찰: `label`·`image` 필드는 **보존**되는 경향(이미지는 별도 에셋 참조), **타입 변경(textfield→text-editor)·필드 순서 변경된 텍스트 필드는 리셋**. 즉 부분 생존은 예측 불가하니 신뢰하지 말 것 — 위 철칙대로.

## CSS cascade · specificity

### 코드위젯 CSS가 아임웹 전역 `.doz_sys h3`·`.doz_sys a` 에 밀림 → ID 스코프로 해결
- **증상**: 코드위젯에 `<style>`로 넣은 `.xxx__h3 { font-size:17px }`, `.xxx__btn { color:#fff }` 이 사이트에서 무시됨. h3가 거대해지고(`.doz_sys h3 { font-size:2.571em }`), 네이비 버튼 안 글자가 검정(`.doz_sys a` color).
- **원인**: 아임웹 테마 전역 CSS가 `.doz_sys h3`·`.doz_sys a` 같은 **class+element 선택자(특이도 0,1,1)** 를 쓰는데, 위젯의 단일 클래스 선택자는 (0,1,0)이라 짐. `blockquote`·`ul`·`strong` 등 요소 선택자 스타일도 같은 경로로 침투.
- **해결**: 코드위젯 루트에 ID를 주고(`id="ajgBrandStory"`) **모든 CSS 규칙을 `#루트ID .클래스`(1,1,0)로 스코프** → `!important` 없이 전역을 이김. 요소 태그(blockquote·ul·a·strong)를 쓰는 곳은 border/font-style/list-style/색을 **명시적으로 재선언**해서 테마 값 상속 차단.
- **부수 규칙**: letter-spacing 미세조정(음수 자간 등)은 넣지 말 것 — 사용자 피드백: "클로드코드 티가 남". 브랜드 톤은 색·굵기·여백으로만.

### color @default 의 알파(투명도)가 실제론 안 먹음 → FF(불투명)로 떨어짐
- **증상**: `@default #33333380`(50%)인데 패널 필드·렌더는 `#333333FF`(불투명). 컬러피커에서 알파 % 줘도 렌더 투명도 안 먹힘.
- **원인**: imweb이 색상값 알파를 불안정하게 처리(8-hex 알파를 FF로 떨굼). §3.3의 "8-hex 알파 지원"과 실제 동작이 다름.
- **해결**: 색(RGB)과 투명도를 **분리**. 컬러는 color 필드, 투명도는 별도 `textfield %` 필드, CSS `color-mix(in srgb, {{color}} {{opacity}}%, transparent)` 로 합성. 토큰 알파와 무관하게 항상 먹는다.
  ```css
  --bg: color-mix(in srgb, {{color-bg}} {{text-bg-opacity}}%, transparent);
  ```

## 프로젝트 구조 · 린트

### `src/` 안이라도 "커스텀 위젯이 아닌 파일"이 있다 → widget-lint 제외
- **증상**: 상품 상세설명용 HTML(`src/detail/*`)을 저장하면 lint가 `인라인 style= 금지`로 막음.
- **원인**: `widget-lint.sh`는 `src/**/*.{html,css,js}`를 전부 **샌드박스 커스텀 위젯**으로 보고 검사. 하지만 같은 `src/` 아래에도 성격이 다른 파일이 섞임:
  - **커스텀 위젯**(`slider/`, `menu/`): 샌드박스 규칙 적용 → 인라인 style·`!important` 금지 ✅ 검사.
  - **상세 에디터 HTML**(`detail/`): 아임웹 상품 상세설명 에디터에 붙여넣는 HTML → **인라인 style 정상**.
  - **DOM 참고본**(`recommend/index.html`, `gnb/index.html`): 아임웹이 뱉은 마크업을 CSS 타겟 잡으려고 보관 → 인라인 style·임의 태그 정상.
  - **헤더 전역 override CSS**(`recommend/overrides.css`): 코드 위젯/헤더 CSS에 넣는 일반 CSS → **`!important` 허용**(샌드박스 아님).
- **해결**: hook에 폴더 제외 case 추가(`detail/`·`recommend/`·`gnb/`). 새 폴더는 **기본 검사**(false positive ＞ false negative — 린터는 기본 검사가 안전). 위젯 아닌 게 확인된 폴더만 추가 제외.
- **부수 효과**: 예전엔 `!important` 쓰려고 override CSS를 `src/` **밖**에 두는 우회를 했는데, 이제 `recommend/`가 제외되어 **`src/` 안에 둬도 됨**.
